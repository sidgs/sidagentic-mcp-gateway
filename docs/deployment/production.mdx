This guide covers the production operating model for sami-mcp-gateway.

When teams want shared access to MCPs in an enterprise environment, Mcpgateway should run in **enterprise mode** with a dedicated PostgreSQL database

That is the mode intended for teams, internal platforms and organizations running Mcpgateway for shared MCP access.

If your goal is simply to use MCPs locally for yourself, development mode is usually a better fit.

## Start in enterprise mode

You can enable enterprise mode in three ways:

<Tabs>
  <Tab title="CLI flag">
    ```bash
    sami-mcp-gateway start --enterprise
    ```
  </Tab>
  <Tab title="Environment variable">
    ```bash
    export SERVER_MODE=enterprise
    sami-mcp-gateway start
    ```
  </Tab>
  <Tab title="Docker Compose">
    Use the production compose file, which sets `SERVER_MODE=enterprise` by default:

    ```bash
    docker compose -f docker-compose.prod.yaml up -d
    ```
  </Tab>
</Tabs>

## First boot and bootstrap admin

On first start in enterprise mode, the server **initializes itself automatically**: it persists the enterprise config, creates the bootstrap admin user, and prints the admin access token once to server logs (stdout). Save that token securely — it is shown only on first bootstrap.

To authenticate your CLI without copying the token from logs, you can optionally run `init-server` from your client machine. That command calls `POST /init` and saves the registry URL and token to `~/.sami-mcp-gateway.conf`.

For bootstrap details and CLI workflow, see:

- [Access and governance overview](/governance/overview)
- [Enterprise operations](/reference/cli-enterprise)

## Recommended runtime pattern

For a shared deployment, the recommended pattern is:

1. Run the standard `ghcr.io/sami-mcp-gateway/sami-mcp-gateway:latest` image.
2. Keep the CLI installed separately on operator machines.
3. Point Mcpgateway at a separate PostgreSQL instance or cluster.

## Run with Docker

For production, use the standard (minimal) Mcpgateway image. It is based on `distroless/base` and contains only the `sami-mcp-gateway` binary.

Supply your database connection string with the `DATABASE_URL` environment variable:

```bash
docker run -d \
  --name sami-mcp-gateway-server \
  -e SERVER_MODE=enterprise \
  -e DATABASE_URL=postgres://user:password@your-db-host:5432/sami-mcp-gateway \
  -p 8080:8080 \
  ghcr.io/sami-mcp-gateway/sami-mcp-gateway:latest
```

<Tip>
  For production, deploy a separate managed Postgres cluster and point `DATABASE_URL` at it rather than running Postgres in the same container. See [Configure Mcpgateway's database](/deployment/database) for all database options.
</Tip>

## Graceful shutdown

Mcpgateway handles `SIGTERM` for graceful shutdown. It closes all active stateful sessions, flushes telemetry, and stops accepting new connections before exiting.

Send `SIGTERM` to stop the server cleanly:

```bash
# For a process running directly
kill -SIGTERM <pid>

# For a Docker container
docker stop sami-mcp-gateway-server
```

`docker stop` sends `SIGTERM` by default, so no extra flags are needed.

## What enterprise mode enables

| Feature | Development mode | Enterprise mode |
|---------|-----------------|-----------------|
| Authentication | Disabled | Required for Users & MCP clients |
| Access control (ACLs) | Disabled | Enabled |
| OpenTelemetry metrics | Disabled (opt-in) | Enabled by default |
| Server initialization | Automatic on first start | Automatic on first start (bootstrap admin token logged once) |

<Info>
  Even in enterprise mode, you can override metrics with `OTEL_ENABLED=false` if needed, though that is not the recommended default for shared deployments.
</Info>
